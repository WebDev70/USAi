# Governance Scorecard

Use periodically to evaluate project-level RAIL health.

Score each category from 1 to 5.

| Category | 1 | 3 | 5 | Score |
|---|---|---|---|---|
| Business alignment | Work lacks clear value | Most work has value | Work is consistently tied to clear outcomes |  |
| Architecture fitness | Fragile or inconsistent | Adequate | Simple, coherent, evolvable architecture |  |
| Engineering quality | Frequent regressions | Mostly stable | Strong tests, reviews, and automation |  |
| Security posture | Reactive | Basic gates | Security shifted left and evidenced |  |
| Process maturity | Ad hoc | Some consistency | RAIL artifacts are complete and useful |  |
| Artifact hygiene | Stale or missing records | Mostly current | Specs, traces, scorecards, and follow-ups are current |  |
| Data/prompt eval quality | Unmeasured | Partially measured | Datasets, prompts, and evals are versioned and reliable |  |

## Escalation rules

- Recurring advisory finding across two reviews should become blocking or receive an owner/date.
- Security, privacy, or data-loss risk may be blocking immediately.
- Process findings should become prompt, eval, checklist, automation, or backlog updates.
