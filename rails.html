The 7 RAIL Roles

0
Product Owner
Features only
Gates the start with a Definition of Ready (user story, testable acceptance criteria, vertical slice, size estimate). Gates the end with acceptance — every criterion verified. Skipped for bugfixes, chores, refactors, and docs.
1
Code Planner
Plan first
Recalls Obsidian memory first. Produces a structured plan: Goal · Files · Approach · Tests · Docs · Risks. Writes docs/specs/<feature>.md before touching a single source file.
2
Architect
Conventions
Validates the design against USAi conventions: no new runtime deps, SSRF guard, path-traversal rejection, CSS ?v=N bump, tool gating via getEnabledTools. Flags conflicts before implementation begins.
3
Developer (SME)
TDD Red→Green→Refactor
Implements exactly what the spec covers (flags scope creep). Writes the failing test first (Red), then minimum code to pass (Green), then cleans up (Refactor). Keeps docs + backlog in sync in the same turn.
4
Tester
Coverage gates
Writes/updates tests in backend/tests/python/ and frontend/tests/js/. Runs ./run-tests.sh --coverage. Gates: Python ≥ 90% lines, JS branch ≥ 70%. Every bug fix gets a regression test.
5
Security
Deterministic scan
Runs ./scripts/security-scan.sh — gitleaks (secrets), bandit (Python SAST), pip-audit (CVEs). Never weaken or disable a scanner to make it pass — fix the finding instead.
6
Reviewer (QA)
All gates must pass
Runs ./scripts/cli-check.sh --review. Compares implementation vs spec line-by-line. Pass only when ALL of: tests green + coverage gates + security scan clean + acceptance criteria met + docs updated + memory note written. On any failure: emits gap list → return to Developer.
TDD inner cycle (inside Developer role)
Step 1 — Red
🔴 Write the test
Write the failing test first. Confirm it fails for the right reason before writing any production code.
Step 2 — Green
🟢 Make it pass
Write the minimum code needed to make the test pass without breaking existing tests.
Step 3 — Refactor
🟡 Clean up
Improve code quality while all tests stay green. Then run the full suite.
Quality axis — advises Roles 2 & 3 on every frontend change

UX & UI SME

UX — How it works

User Experience

Ensures the feature solves a real user problem and fits naturally into the user's journey — before a pixel of CSS is written.

◆ User-need framing: every control maps to a stated user task in the spec or docs/USER_GUIDE.md.
◆ User-flow / journey mapping: multi-step interactions have a sentence-level flow (e.g. "user clicks X → Y appears → confirms → Z") before implementation.
◆ Information architecture & placement: new controls are placed in the section that matches their conceptual function — cross-checked against USER_GUIDE.md headings.
◆ Friction audit: the happy path can be completed without back-tracking; error states are named; task completion is verifiable.
UI — How it looks

User Interface

Ensures the graphical elements are cohesive, accessible, and coded to USAi standards — no framework, no magic values.

◆ Vanilla CSS & JS only: no framework, no build step, no new runtime dependency.
◆ Token-driven design: colours, radii, shadows use --color-* / --radius-* tokens; works in both light and dark themes.
◆ WCAG AA accessibility: ≥ 4.5:1 contrast, :focus-visible on interactive elements, semantic HTML, aria-label on icon-only controls.
◆ Motion guard: non-essential animation wrapped in @media (prefers-reduced-motion: reduce).
◆ CSS cache bust: any styles.css edit bumps ?v=N in index.html.
Not a sequential role. The UX & UI SME is a quality axis that advises the Architect (Role 2) during design and the Developer (Role 3) during implementation. It surfaces via the ui-ux-review QA gate (Reviewer Role 6) and the /sme-frontend workflow.
Cadence roles — per-sprint or on-demand

Sprint-Level Oversight

🏛
/govern

Governance Board

Four-role macro-assessment at every sprint close: SBA (business alignment) · SA (architecture fitness) · SE (engineering quality) · SPMS (process maturity). Findings are BLOCKING / ADVISORY / INNOVATION. Backlog items are added for any BLOCKING finding.

🧹
/housekeep

Senior Housekeeping & Hygiene Steward (SHK)

Repo hygiene sweep: spec/backlog reconciliation, dead-code audit, log & cache bloat, doc-consistency drift, dependency freshness, vault memory hygiene. Runs automatically as Role 5 in /govern, or standalone via /housekeep. A lightweight leave-no-trace gate also runs inside every /loop.

Always-on non-negotiables

The Rules

🔐
Secrets
Never commit or echo secrets. API keys live only in .env (git-ignored). /config returns only has_* boolean flags — never raw keys.
📝
Docs in sync
CHANGELOG on every substantive change. USER_GUIDE for user-facing features. README for setup/config. Backlog lifecycle updated in the same turn.
🧠
Memory
Recall from Obsidian vault at task start. Record a session note to Cline/memories/ at task end. Context must survive across sessions.
🎨
CSS cache bust
Any edit to styles.css requires bumping the ?v=N query string in index.html to prevent stale cache.
🧹
Housekeeping
Leave-no-trace gate inside every /loop pass. Full SHK sweep runs automatically at sprint close via /govern.

All Workflows

/spec
Plan Mode
Specification Writer
Interviews the user, validates architecture, runs shift-left governance, writes docs/specs/<feature>.md, and marks item In Progress in backlog.
/loop
Act Mode
Orchestration Loop
Drives /build → /review repeatedly until all Done criteria pass. Handles escalation if stuck. Closes backlog item to Done on success.
/build
Act Mode
Implementation
Implements the spec exactly. TDD: Red receipt (failing test) first, then Green (minimum code), then Refactor. Flags any spec deviation immediately.
/review
Act Mode
QA Review
Runs all 10 QA gates (coverage, security scan, doc-consistency, spec-check, acceptance criteria, DoD). Emits gap list on failure; returns to Developer.
/govern
Sprint-close / on-demand
Governance Board
Full 5-role sprint-close audit: SBA · SA · SE · SPMS · SHK. Produces BLOCKING/ADVISORY/INNOVATION findings. Feeds results into backlog.
/housekeep
On-demand
Standalone Hygiene Sweep
Runs the SHK sweep in isolation: spec/backlog reconciliation, dead-code, log bloat, doc drift, dependency freshness, vault hygiene.
/self-improve
Any mode
Self-scoring Rewrite
Scores output 1–10 on correctness/clarity/coverage/style. Rewrites until ≥ 9 or 3 iterations. Shows only final output + last score.
/sme-backend
Act Mode
Backend SME
Domain-specific helper for server.py and Python backend work: endpoint patterns, security guards, stdlib-only conventions.
/sme-frontend
Act Mode
UX & UI SME (Frontend)
UX: user-need framing, flow mapping, IA placement vs USER_GUIDE, friction audit. UI: vanilla CSS/JS, token system, WCAG AA, CSS ?v=N cache-bust, no-framework rule.
/sme-docs
Act Mode
Docs SME
Domain-specific helper for documentation work: CHANGELOG format, USER_GUIDE style, spec authoring, README maintenance, consistency checks.
